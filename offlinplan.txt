# Offline Resilience Plan

## Problems Identified

### 1. Audio cache is wiped on version change
In `sw.ts`, the audio cache is named `quran-audio-cache-${VERSION}` (e.g. `quran-audio-cache-v0.1.3`).
When VERSION changes, old caches are invalidated and the user loses all downloaded audio.
Meanwhile, `AudioPlayer.tsx` and `DownloadManager.tsx` use a **fixed** name `"quran-audio-cache"` — 
so there's already a mismatch between the SW cache and the app-level cache.

### 2. Download button visible when offline
The "📥 تحميل" button in the header (`page.tsx` line 35-41) is always visible.
Clicking it while offline opens DownloadManager which will fail to fetch audio files.

### 3. Connectivity check is too simple for restricted networks
`useConnectivity.ts` pings `HEAD /` to check connectivity. On captive portals,
hotel Wi-Fi, or networks that only allow social media, the ping returns `200 OK`
even though the audio server is unreachable. This means:
- The app thinks it's online when it can't actually download audio
- Downloads fail silently or with generic errors
- PwaUpdater allows updates that will fail

## Proposed Changes

### Change 1: Persistent audio cache (never delete downloaded audio)

**File: `src/app/sw.ts`**
- Remove VERSION from the audio cache name: `"quran-audio-cache"` (matches what components already use)
- Keep VERSION in the other caches (pages, static assets) — those should refresh on updates
- This way audio files survive version bumps

```diff
- cacheName: `quran-audio-cache-${VERSION}`,
+ cacheName: "quran-audio-cache",
```

### Change 2: Hide download button when offline

**File: `src/app/page.tsx`**
- Import and use `useConnectivity` hook
- Conditionally render the download button only when `isOnline` is true

```diff
+ const { isOnline } = useConnectivity();
  ...
- <button className="download-header-btn" onClick={() => setDownloadOpen(true)}>
-   📥 تحميل
- </button>
+ {isOnline && (
+   <button className="download-header-btn" onClick={() => setDownloadOpen(true)}>
+     📥 تحميل
+   </button>
+ )}
```

### Change 3: Reliable connectivity — verify actual audio server reachability

**File: `src/lib/useConnectivity.ts`**
- Add a second check: after the HEAD / ping succeeds, also try to reach the audio
  endpoint (e.g. a tiny HEAD request to one known audio URL or a dedicated /api/health endpoint)
- Add a `connectionQuality` state: "online" | "restricted" | "offline"
- If HEAD / succeeds but audio server is unreachable → "restricted"
- This prevents download attempts on captive portals / restricted Wi-Fi

The ping strategy:
1. `HEAD /` — checks basic web connectivity (catches full offline)
2. `HEAD /audio/001/001_1.mp3` (range: bytes=0-0) — checks audio server reachability
   (catches captive portals, restricted networks)
   If step 1 passes but step 2 fails → restricted network

```diff
  async function pingServer(): Promise<boolean> {
+   // Phase 1: check basic connectivity
    ...
    return res.ok;
  }

+ async function pingAudioServer(): Promise<boolean> {
+   const controller = new AbortController();
+   const timer = setTimeout(() => controller.abort(), PING_TIMEOUT_MS);
+   try {
+     const res = await fetch("/audio/001/001_1.mp3", {
+       method: "HEAD",
+       cache: "no-store",
+       signal: controller.signal,
+     });
+     // Must be audio content, not a captive portal HTML page
+     const ct = res.headers.get("content-type") || "";
+     return res.ok && (ct.includes("audio") || ct.includes("octet-stream"));
+   } catch {
+     return false;
+   } finally {
+     clearTimeout(timer);
+   }
+ }
```

**File: `src/components/DownloadManager.tsx`**
- Import `useConnectivity`
- Before starting a download, call `verify()` to confirm real connectivity
- If connectivity is restricted, show an error message in Arabic:
  "الإنترنت متصل لكن الخادم غير متاح. تأكد من اتصالك بإنترنت غير مقيد"
  (Internet is connected but server is unreachable. Make sure you have unrestricted internet)

**File: `src/components/PwaUpdater.tsx`**
- Already checks connectivity before updating — good
- Add the audio-server check so updates aren't attempted on restricted networks

### Change 4: Also hide the download button during DownloadManager if connection drops

**File: `src/components/DownloadManager.tsx`**
- Watch `isOnline` from useConnectivity
- If connection drops mid-download → pause/abort the download & show error
- This handles the case where Wi-Fi drops while downloading
